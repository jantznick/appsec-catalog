Building a modern Application Security Program

Embed security into software delivery across Hearst by combining executive visibility, consistent lifecycle standards, practical engineering controls, and a community that helps teams improve quarter after quarter.

Visibility Assurance Governance Secure delivery

Program Goals

1. VisibilityKnow what applications exist, who owns them, and where they run.
2. AssuranceApply appropriate testing, gates, and controls based on application risk.
3. GovernanceMeasure, report, and continuously improve security outcomes.
Security becomes part of the development process, not a gate at the end.
Why This Matters

Security needs to scale with development velocity.

The current pain is not a lack of security activity. It is fragmented visibility, inconsistent testing, manual review cycles, and reporting that is hard to use at leadership level.

Program Framework

The full-circle AppSec lifecycle.

The deck’s six-stage lifecycle becomes the operating rhythm for real engineering work: design guidance, automated feedback, release checks, runtime monitoring, and improvement planning.

01

Plan & Design

Application intake, ownership, data flow, architecture review, and threat modeling.

02

Build & Commit

SAST, SCA, secure coding guidance, repo visibility, and fast developer feedback.

03

CI Security Gates

Policy checks, blocking criteria, scan freshness, exceptions, and release evidence.

04

Release & Deploy

Artifact validation, DAST scheduling, approval workflow, and remediation tracking.

05

Runtime Operations

WAF, API security, domain monitoring, production issue response, and exposure review.

06

Improve & Govern

Scorecards, SAMM maturity, quarterly reviews, control adoption, and executive reporting.

Technical Work

What the program actually builds and operates.

This is the bridge between the high-level strategy and the day-to-day AppSec work: inventory, tool integration, gates, evidence, remediation, and the reporting layer that turns the work into decisions.

Operating Model

Security as an enabler, not a gatekeeper.

The central team owns the program system: policy, tooling, governance, reporting, and oversight. Business engineering teams execute the practices, maintain evidence, remediate findings, and own application risk.

ASCOE

Center of Excellence turns standards into adoption.

Tools and policy are not enough. The AppSec Center of Excellence creates the community layer: developers, security leaders, champions, workshops, shared wins, and feedback loops.

Connect. Collaborate. Elevate. Secure. A community driving secure software delivery across Hearst.
