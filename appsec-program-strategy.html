Service Catalog

The program is a set of services teams can actually use.

Each service either reduces uncertainty, prevents new vulnerabilities from entering the SDLC, finds issues before release, or protects production while teams remediate.

Foundation

Application Onboarding

Capture ownership, architecture, repo, runtime, auth, data sensitivity, domains, and deployment context.

  • Application onboarding questionnaire
  • Posture analysis baseline
  • Portfolio map and ownership model
Design

Threat Modeling

Use lightweight STRIDE sessions to identify trust boundaries, abuse cases, and mitigations before code lands.

  • Data flow diagrams
  • Security design review
  • Developer-led workshops
Verification

Code and Dependency Scanning

Integrate Snyk for SAST and SCA so teams get fast feedback in pull requests and pipelines.

  • Vulnerable code detection
  • Open-source dependency risk
  • License and IaC visibility
Runtime

DAST, API, and WAF Coverage

Use Tenable WAS, Traceable, and Fastly NGWAF where risk warrants runtime testing and edge protection.

  • Staging DAST before major release
  • API discovery and abuse detection
  • Managed edge enforcement
Assurance

Penetration Testing

Collaborative testing that validates real exploitability and produces remediation guidance tied to root cause.

  • Web, mobile, network, and cloud scope
  • Rules of engagement
  • Remediation tracking
Monitoring

Domain Monitoring

Watch registrations, certificate transparency, and phishing sources for brand impersonation and abuse.

  • Suspicious domain discovery
  • Alert triage
  • Takedown coordination
Maturity

SAMM Assessments

Measure governance, design, implementation, verification, and operations maturity using a shared framework.

  • Interviews and evidence
  • Score and gap analysis
  • 6-12 month roadmap workshop
Enablement

Developer Guidance

Give engineers concise patterns, checklists, and training so secure behavior is repeatable without waiting on a review.

  • Secure coding checklist
  • Threat modeling training
  • Policy and control guidance
Lifecycle

Security moves with the application, not after it.

The program creates a durable loop from inventory to design, delivery, production, and maturity planning. Every pass through the loop improves both the application and the evidence we hold about it.

01 - Know

Inventory and context

Owner, repository, framework, deployment model, domains, authentication, and data classification.

02 - Design

Threats and mitigations

Data flow, trust boundaries, STRIDE prompts, security requirements, and architecture decisions.

03 - Build

Automated feedback

SAST, SCA, dependency risk, license checks, and developer remediation guidance in CI/CD.

04 - Run

Runtime validation

DAST, API security, WAF posture, domain monitoring, and production exposure review.

05 - Improve

Score and roadmap

Scorecards, quick wins, SAMM maturity, retesting, and recurring cadence meetings.

Operating Model

How work enters the program and turns into measurable risk reduction.

AppSec acts as the connective tissue between engineering teams, security platforms, risk context, and leadership reporting. The catalog is the front door; the scorecard is the feedback loop.

Tooling Layer

Managed controls are matched to application risk.

Not every application needs the same depth of tooling on day one. The program assigns controls based on exposure, data sensitivity, criticality, and deployment activity.

Measurement

The score turns program coverage into decisions.

The application security score combines knowledge sharing and tool usage. Weighting changes by importance so high-risk applications are pushed toward stronger controls while lower-risk applications first improve completeness and ownership.

Security Score
100

Not a vanity metric. The score is a routing mechanism: what do we know, which controls are active, what is stale, and what is the quickest responsible improvement?

Knowledge SharingMetadata + review freshness
Description, team contact, repository, language, framework, server environment, authentication profiles, and data types.
Tool UsageCoverage + integration depth
SAST, DAST, application firewall, and API security are weighted by quality, integration level, risk factors, and active usage.
Importance WeightingRisk changes the math
High-importance apps favor tool usage. Lower-importance apps can gain more through complete, accurate documentation.
Quick WinsActionable next step
The score breakdown should show the lowest-effort changes that most improve the application posture.
Customer Roadmap

A clear path from first conversation to continuous improvement.

This mirrors the new-customer journey: establish a baseline, integrate tools, onboard applications, then mature through cadence meetings, testing, and SAMM-informed planning.

Weeks 1-2

Foundation and onboarding

  • Initial contact and scoping conversation
  • Posture analysis questionnaire
  • Onboarding meeting and AppSec service overview
  • Initial quarter roadmap for priority actions
Weeks 3-6

Integration and first services

  • SAST and SCA tool integration in CI/CD
  • First application profile and scorecard
  • Developer training and threat modeling guidance
  • Control selection based on risk and exposure
Ongoing

Maturity and continuous improvement

  • Recurring cadence meetings and score review
  • Penetration testing and DAST as applications mature
  • SAMM assessment after roughly six months
  • Evidence-driven roadmap for the next 6-12 months
What Success Looks Like

The program creates shared visibility and repeatable action.

Leadership gets a portfolio-level view of risk. Engineering teams get practical help. AppSec gets evidence that stays current. The business gets a way to move faster with fewer unknowns.

For teams

Clear front door

Teams know how to engage AppSec, which services exist, and what to do next when their score changes.

For AppSec

Current evidence

Application metadata, tool state, scan freshness, and maturity work all connect to a shared catalog.

For leaders

Risk-aware prioritization

Portfolio reporting shows where coverage is strong, where exposure is high, and where investment matters most.
